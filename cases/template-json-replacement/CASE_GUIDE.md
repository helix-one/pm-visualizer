# 模板案例：先看最终效果，再追数据流

在工作台选择“个人模板”或“官方更新”。顶部“最终效果”可直达用户会看到的页面；点节点可看它接收什么、产出什么及对应代码；“查看全图”可看上下游。两张图是对**当前本地代码**的手工分析，不表示已在生产发布。

## 个人微调：一个用户会得到什么

个人提交的是定点修改固定文字和提示的 **override JSON**，不是最终完整模板。系统以官方模板为底稿，按适用年份生成完整 `templateSections` 快照及个人 PDF；两者一起保存在主数据库 `user_template_releases` 的用户专属记录中，不覆盖官方模板，也不是为每人建一个数据库。个人微调不会增删、重排 Q 槽位或改变其可选性，答题卡仍最多 24 槽。

| 用户看到的效果 | 数据怎样到达那里 |
| --- | --- |
| “我的专属模板” PDF | 完整个人版本生成 PDF → 按 `user_id` 保存 → 登录用户从资料页下载；其他用户和公开 PDF 不受影响。 |
| 新训练中的 Q1/Q2、固定句和提示 | 按用户、英语一/二、作文类型和年份选个人版；没有则回退官方版 → 新会话固定完整模板快照 → `/training/templates/year` 返回该会话模板 → 前端从 `templateSections` 派生 Q 键、顺序和正文。不是前端直接读个人原始 JSON。 |
| 提交后的作文与批改回看 | 填答携带会话 ID 提交 → 后端用同一会话快照拼作文，并为尝试保存模板快照 → 回看按该快照对准原 Q 键与反馈。 |

“快照”就是当时**完整模板的一份固定副本**，不是只保存改动差异。发布新个人版后，已创建的活动/历史会话仍使用旧副本；通常要开启新会话才会看到新版本。真题题干来自另一个题目数据源，不会因为修改模板 JSON 自动改变。

## 官方更新：两条发布命令、两种效果

官方更换源 JSON/registry 后，后端命令逐年编译并校验模板，生成公开 PDF、catalog 和发布记录；前端同步命令再更新小程序资料目录与缓存版本。同步并部署后，用户才看到新的公开 PDF。新训练则按考试类型、作文类型及年份加载官方模板，Q1/Q2、固定句与提示跟着当年模板变化；已创建会话仍用自己的旧快照。PDF 还有独立内容 package，改 JSON 时须核对两者一致。完整路径在 `official-process.json` 中。

这轮只补清晰展示与文档，没有改模板业务代码、执行发布命令或增加 Phase 1 能力。
